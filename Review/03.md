# ЧАСТЬ 3. Confusion Matrix, Precision/Recall/F1/Fβ и ловушка Accuracy

**Цель:** уметь по одной табличке 2×2 восстановить любую метрику классификации, объяснить бизнес-смысл каждой из них и с ходу назвать пример, где Accuracy формально «хорошая», а модель — бесполезна.

---

## 1. Confusion Matrix (матрица ошибок)

Для бинарной классификации все возможные исходы сравнения предсказания `ŷ` с истинной меткой `y` укладываются в четыре ячейки:

| | Предсказан 1 (Positive) | Предсказан 0 (Negative) |
|---|---|---|
| **Истина 1** | **TP** (True Positive) | **FN** (False Negative) |
| **Истина 0** | **FP** (False Positive) | **TN** (True Negative) |

Терминология из статистики, которая иногда всплывает на собеседовании отдельно:
- **FP — ошибка I рода** (ложная тревога: сказали «да», хотя было «нет»);
- **FN — ошибка II рода** (пропуск цели: сказали «нет», хотя было «да»).

Все метрики классификации, о которых пойдёт речь, — это разные способы «свернуть» четыре числа `TP, TN, FP, FN` в одно, каждый со своим акцентом на то, какая из ошибок дороже.

---

## 2. Accuracy и её парадокс

```
Accuracy = (TP + TN) / (TP + TN + FP + FN)
```

Доля верных ответов среди всех предсказаний — самая интуитивная метрика и самая опасная при дисбалансе классов.

**Проверенный численный пример.** 1000 транзакций, из них 990 легитимных и 10 мошеннических (1% — типичный порядок для реального антифрода). «Модель», которая **всегда** предсказывает «не фрод», не видя данных вообще:

| Метрика | Значение |
|---|---|
| Accuracy | **0.9900** |
| Precision | 0.0000 |
| Recall | **0.0000** |

99% точности — и при этом модель не поймала вообще ни одного мошенника. Это не гипотетический крайний случай, а прямое следствие формулы: при доле положительного класса `p`, Accuracy константного «всегда 0»-классификатора равна `1 − p` — чем реже случается целевое событие, тем выше будет казаться Accuracy у модели, которая полностью его игнорирует. **Правило для собеседования:** Accuracy — осмысленная метрика только при сбалансированных классах (или близко к тому); при сильном дисбалансе она систематически завышает впечатление о качестве.

---

## 3. Precision (точность)

```
Precision = TP / (TP + FP)
```

«Из всех объектов, которые модель назвала положительными — какая доля действительно положительна?» Precision отвечает за **цену ложной тревоги (FP)**.

**Когда Precision критичен:** рассылка дорогих печатных каталогов, блокировка карты клиента как подозрительной, показ рекламы узкому таргетированному сегменту — везде, где ложное срабатывание стоит реальных денег или раздражает добросовестного пользователя.

---

## 4. Recall (полнота, он же Sensitivity, True Positive Rate)

```
Recall = TP / (TP + FN)
```

«Из всех действительно положительных объектов — какую долю модель нашла?» Recall отвечает за **цену пропуска (FN)**.

**Когда Recall критичен:** медицинский скрининг (пропущенная опухоль стоит несравнимо дороже лишнего направления на дополнительное обследование), антифрод (пропущенная крупная мошенническая транзакция может стоить компании больше, чем сотня ложных блокировок), поиск дефектов на производственной линии.

**Ключевая связь:** Precision и Recall обычно находятся в обратной зависимости — при понижении порога классификации (модель охотнее говорит «1») Recall растёт (ловим больше положительных), а Precision падает (растёт число ложных срабатываний), и наоборот. Полная геометрия этого компромисса — в Части 4 (PR-кривая).

---

## 5. F1-score: почему гармоническое, а не арифметическое среднее

```
F1 = 2 · Precision · Recall / (Precision + Recall)
```

Это гармоническое среднее Precision и Recall. Возникает закономерный вопрос: почему не просто `(Precision + Recall) / 2`?

**Проверенный численный пример.** Возьмём вырожденный случай: `Precision = 1.0`, `Recall ≈ 0.0001` (модель почти никогда не срабатывает, но когда срабатывает — всегда права; классический "трусливый" классификатор).

| Способ усреднения | Значение |
|---|---|
| Арифметическое среднее `(P+R)/2` | **0.5000** |
| Гармоническое среднее (F1) | **0.0002** |

Арифметическое среднее говорит «модель на 50% хороша» — абсурдный вывод для классификатора, который практически ничего не находит. **Гармоническое среднее сильно штрафует за то, что хотя бы одна из двух величин близка к нулю** — это его ключевое математическое свойство: гармоническое среднее двух чисел всегда ≤ их арифметического среднего, и разрыв тем больше, чем сильнее числа отличаются друг от друга. F1 корректно отражает: модель, которая не находит почти ничего, — плохая модель, независимо от того, насколько точны её редкие срабатывания.

---

## 6. Fβ-мера: взвешенное гармоническое среднее

F1 придаёт Precision и Recall равный вес — но бизнес-контекст редко симметричен. Общая формула:

```
Fβ = (1 + β²) · Precision · Recall / (β² · Precision + Recall)
```

**Интерпретация параметра β:**
- **β = 1** — F1, равный вес Precision и Recall;
- **β < 1** (например, `β = 0.5`) — больший вес Precision (штрафуем за ложные срабатывания сильнее);
- **β > 1** (например, `β = 2`) — больший вес Recall (штрафуем за пропуски сильнее) — именно такая настройка типична для медицинского скрининга, где цена пропущенного случая заболевания несопоставимо выше цены лишней перепроверки.

**Проверенный численный пример** на асимметричных Precision и Recall (`Precision = 0.6429`, `Recall = 0.9000` — типичная картина классификатора с низким порогом отсечения, настроенного «ловить всё»):

| β | Fβ | Комментарий |
|---|---|---|
| 0.5 | **0.6818** | ближе к Precision (0.6429) — штрафует за низкую точность |
| 1.0 | **0.7500** | ровно посередине между гармоническими весами |
| 2.0 | **0.8333** | ближе к Recall (0.9000) — вознаграждает высокую полноту |

Видно наглядно: чем больше `β`, тем ближе итоговое значение к Recall и тем меньше модель штрафуется за посредственную Precision. Это прямой математический механизм того, что в задании про медицинский скрининг с `β=2` правильный ответ — «минимизировать количество FN» (пропусков): формула буквально придаёт квадратичный вес `β²=4` именно Precision в знаменателе, ослабляя относительный вклад пропусков (FN сидит только в Recall) в итоговый штраф.

## 7. Полный воркед-пример (сквозной расчёт вручную и сверка с sklearn)

20 транзакций: 10 истинно мошеннических, 10 легитимных.

```
TP = 7   (мошенничество, поймано)
FN = 3   (мошенничество, пропущено)
TN = 7   (легитимная, верно пропущена)
FP = 3   (легитимная, ложно заблокирована)
```

| Метрика | Ручной расчёт | sklearn |
|---|---|---|
| Precision | 7/(7+3) = **0.7000** | 0.7000 |
| Recall | 7/(7+3) = **0.7000** | 0.7000 |
| F1 | 2·0.7·0.7/(0.7+0.7) = **0.7000** | 0.7000 |
| Accuracy | (7+7)/20 = **0.7000** | 0.7000 |

Здесь Precision и Recall случайно совпали (симметричная матрица ошибок), поэтому все Fβ дают одно и то же значение 0.7 — хороший тест-кейс для проверки корректности реализации формул (если у вас Fβ-функция написана руками, симметричный случай — быстрая sanity-проверка перед тем, как переходить к асимметричным данным).

## 8. Бизнес-таблица выбора метрики

| Сценарий | Что дороже | Что оптимизировать |
|---|---|---|
| Антифрод (блокировка карты) | FP раздражает клиента, но не смертельно; крупный пропущенный фрод — прямые убытки | Recall или Fβ, β>1 |
| Спам-фильтр | FP (важное письмо в спаме) хуже, чем FN (спам в инбоксе) | Precision или Fβ, β<1 |
| Медицинский скрининг | Пропуск диагноза (FN) может стоить жизни | Recall или Fβ, β=2 и выше |
| Рассылка дорогих печатных каталогов | Каждый FP — прямые деньги на ветер | Precision |
| Модерация контента (жёсткий фильтр) | Зависит от политики — часто симметрично | F1 |

---

## Ключевые тезисы

1. Все метрики классификации — это разные функции от четырёх чисел `TP, TN, FP, FN`.
2. Accuracy обманчива при дисбалансе классов: тривиальная константная модель может показать `Accuracy = 1 − p`, где `p` — доля редкого класса, не поймав ни одного целевого объекта.
3. Precision отвечает за цену FP, Recall — за цену FN; они обычно находятся в обратной зависимости при изменении порога.
4. F1 — гармоническое, а не арифметическое среднее — потому что гармоническое среднее жёстко штрафует за то, что хотя бы одна из величин (P или R) близка к нулю, тогда как арифметическое среднее такую ситуацию маскирует.
5. Fβ — обобщение F1 с настраиваемым весом: `β>1` смещает акцент на Recall (β=2 — классика медицинского скрининга), `β<1` — на Precision.

## Вопросы для самопроверки

1. У вас 100 000 транзакций, из них 50 мошеннических. Модель, всегда предсказывающая «не фрод», получает какую Accuracy? Посчитайте точно.
2. Постройте свой пример, где `Precision = 0.9`, `Recall = 0.1`, и вручную посчитайте F1, F0.5 и F2. Убедитесь, что F0.5 > F1 > F2 (в эту сторону, потому что здесь именно Precision высок, а не Recall).
3. Почему для задачи «найти как можно больше потенциальных мошенников, даже ценой большого числа ложных проверок» неверно оптимизировать F0.5?
4. Есть ли ситуация, где Precision и Recall совпадают, но матрица ошибок при этом не симметрична (`TP≠TN` или `FP≠FN`)? Приведите числовой пример или объясните, почему это невозможно.

| «У вас 1% положительного класса, слабая модель показывает Accuracy 99%. Хорошая ли это модель?» | Нет — при доле положительного класса 1% даже тривиальная модель, всегда предсказывающая «отрицательный класс», получит Accuracy 99%, не поймав ни одного целевого объекта. Accuracy здесь бессмысленна; нужно смотреть Precision/Recall/F1 или PR-AUC. |
| «Почему F1 — гармоническое среднее, а не арифметическое?» | Гармоническое среднее сильно штрафует ситуацию, когда одна из величин (Precision или Recall) близка к нулю — в отличие от арифметического среднего, которое такую асимметрию сглаживает и может дать обманчиво высокое значение даже для практически бесполезной модели. |
| «Вы настраиваете модель для медицинского скрининга и используете Fβ с β=2. Какое поведение вы поощряете?» | Минимизацию FN (пропусков) сильнее, чем минимизацию FP: β²=4 в знаменателе формулы ослабляет относительный вес Precision, отдавая приоритет Recall — что соответствует бизнес-логике «лучше лишний раз перепроверить здорового, чем пропустить больного». |
| «В чём разница между ошибкой I и II рода применительно к Precision и Recall?» | Ошибка I рода (FP) снижает Precision, ошибка II рода (FN) снижает Recall — это два независимых канала ошибки, которые нельзя одновременно минимизировать без компромисса, задаваемого порогом классификации. |
