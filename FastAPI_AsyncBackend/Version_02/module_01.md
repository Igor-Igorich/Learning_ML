## 1.1. Функции — это тоже объекты

В Python есть одно правило, из которого вытекает почти всё остальное: **абсолютно всё, что можно положить в переменную, — это объект**. Число `5` — объект. Строка `"привет"` — объект. И функция, которую ты определяешь через `def`, — тоже самый обычный объект, ничем принципиально не отличающийся от числа или строки с точки зрения того, что с ним можно делать.

```python
def greet(name):
    return f"Привет, {name}!"

func_ref = greet          # без круглых скобок!
print(type(greet))        # <class 'function'>
print(func_ref("Игорь"))  # Привет, Игорь!
```

Здесь важно различать две вещи, которые внешне похожи, но означают совершенно разное:

- `greet` (без скобок) — это **сама функция как объект**, ссылка на неё. Ты можешь положить её в переменную (`func_ref = greet`), передать куда-то, вернуть откуда-то — и при этом функция ни разу не выполнится.
- `greet(...)` (со скобками) — это **вызов** функции: «выполни её тело прямо сейчас и дай мне результат».

`type(greet)` печатает `<class 'function'>` — то есть у функции, как у любого объекта в Python, есть тип, и этот тип называется `function`. Это не какая-то особая синтаксическая конструкция языка — это обычный объект определённого типа, просто с ним удобно работать через специальный синтаксис `def` и вызов через `()`.

Забегая совсем немного вперёд (без деталей — это тема модуля 4): когда мы в будущем напишем `async def some_function(): ...`, то `some_function` тоже будет самым обычным объектом, который можно положить в переменную, не вызывая. Разница появится в том, что происходит при вызове `some_function()` — но сам факт «функция — это объект, а не какая-то особая магическая штука» будет работать точно так же.

## 1.2. Функции как аргументы и как результат

Раз функция — обычный объект, её можно передавать в другие функции точно так же, как число или строку. Функцию, которая принимает другую функцию как аргумент или возвращает функцию в качестве результата, называют **функцией высшего порядка** — простой термин без всякой магии за ним, просто «функция, которая работает с другими функциями как со значениями».

```python
def apply_twice(func, value):
    return func(func(value))

def add_one(x):
    return x + 1

print(apply_twice(add_one, 5))  # 7
```

Здесь `apply_twice` не знает заранее, что именно ей передадут — она просто дважды вызывает то, что ей дали, называя это `func`. Мы передали `add_one` (снова без скобок — мы передаём саму функцию, а не результат её вызова), и `apply_twice` дважды применила её: `add_one(add_one(5))` = `add_one(6)` = `7`.

Функция может и **возвращать** другую функцию:

```python
def make_multiplier(factor):
    def multiplier(x):
        return x * factor
    return multiplier

times3 = make_multiplier(3)
print(type(times3))  # <class 'function'>
print(times3(10))    # 30
```

Тут происходит кое-что интересное: внутри `make_multiplier` мы определили ещё одну функцию — `multiplier` — прямо внутри другой функции, и вернули её наружу. `times3` — это и есть та самая внутренняя функция `multiplier`, только с уже «встроенным» значением `factor = 3`. Как именно `multiplier` умудряется «помнить» число `3` уже после того, как `make_multiplier` закончила работу и её локальные переменные, казалось бы, должны были исчезнуть, — разберём в следующем пункте.

Зачем это вообще нужно на практике: в FastAPI ты будешь постоянно передавать функции как значения — в `Depends(get_db)` ты передаёшь функцию `get_db`, а не результат её вызова; в декораторах (если ты их уже видел раньше) функция оборачивается другой функцией. Всё это работает только потому, что в Python функция — равноправное значение, а не особая синтаксическая конструкция.

## 1.3. Замыкания (closures)

В примере выше внутренняя функция `multiplier` использует переменную `factor`, которая ей не принадлежит — `factor` это параметр внешней функции `make_multiplier`. Когда внутренняя функция «запоминает» переменные из окружающей её функции и продолжает иметь к ним доступ даже после того, как внешняя функция завершилась, — это называется **замыканием**.

Разберём это на более наглядном примере — счётчике:

```python
def make_counter():
    count = 0
    def counter():
        nonlocal count
        count += 1
        return count
    return counter

c1 = make_counter()
c2 = make_counter()

print(c1(), c1(), c1())  # 1 2 3
print(c2())               # 1
```

Что здесь происходит по шагам:

1. `make_counter()` создаёт локальную переменную `count = 0` и определяет внутреннюю функцию `counter`, которая эту переменную использует.
2. `make_counter` возвращает `counter` и завершает работу. Казалось бы, `count` должна была исчезнуть вместе с завершившейся функцией — так происходит с обычными локальными переменными. Но `counter` **держит на неё ссылку**, и поэтому Python не удаляет `count` из памяти — она продолжает жить, «замкнутая» внутри `counter`.
3. Каждый раз, когда мы вызываем `c1()`, выполняется тело `counter`, которое увеличивает именно ту `count`, что была создана в конкретном вызове `make_counter()`.
4. `c1` и `c2` созданы двумя **разными** вызовами `make_counter()`, поэтому у каждого — своя, независимая переменная `count`. `c1()` три раза подряд даёт `1, 2, 3`, а `c2()` в первый же вызов снова начинает с `1` — потому что это совсем другая, отдельная `count`.

Про слово `nonlocal`: по умолчанию, если внутри функции написать `count = count + 1`, Python решит, что ты создаёшь **новую локальную** переменную `count` внутри `counter`, и упадёт с ошибкой («использовать переменную до присваивания»), потому что справа `count` ещё не существует в локальной области видимости. Ключевое слово `nonlocal count` явно говорит Python: «не создавай новую локальную переменную, а используй ту, что находится в объемлющей функции». Без `nonlocal` замыкание можно только *читать*, но не *изменять* — это частая ошибка новичков.

Можно даже заглянуть внутрь и увидеть, что именно "замкнула" функция — Python хранит замкнутые значения в специальном атрибуте `__closure__`:

```python
print(c1.__closure__[0].cell_contents)  # 3
```

Это подтверждает: замыкание — не «функция запомнила число 3 навсегда», а «функция держит живую ссылку на переменную, и эта переменная сейчас равна 3» (после трёх вызовов `c1()`).

Где это пригодится дальше в курсе: замыкания — это ровно тот механизм, на котором в Python строятся декораторы и многие функции-зависимости в FastAPI (модуль 9, Dependency Injection) — функция, которая «настраивается» один раз параметрами, а потом переиспользуется, помня эти параметры.

## 1.4. Протокол итератора: что на самом деле делает `for`

Ты наверняка писал `for x in some_list: ...` бесчисленное количество раз. За этим простым синтаксисом стоит чёткий, документированный механизм, который называется **протоколом итератора**. Важно разобраться в нём, потому что асинхронная версия цикла — `async for`, с которой мы встретимся в модуле 4 — устроена буквально по тем же правилам, только с приставкой «асинхронный» у каждого шага.

Когда Python выполняет:

```python
for x in [10, 20, 30]:
    print(x)
```

на самом деле происходит следующее (это не метафора — можно написать вручную и убедиться, что результат идентичный):

```python
iterator = iter([10, 20, 30])   # вызывает __iter__() у списка
while True:
    try:
        x = next(iterator)      # вызывает __next__() у итератора
        print(x)
    except StopIteration:
        break
```

Здесь используются две встроенные функции Python:

- `iter(obj)` — вызывает у `obj` специальный метод `__iter__()` и возвращает **итератор**: объект, который умеет отдавать значения по одному.
- `next(iterator)` — вызывает у итератора метод `__next__()` и возвращает следующее значение. Когда значения закончились, `__next__()` поднимает исключение `StopIteration` — именно по этому исключению цикл `for` понимает, что пора остановиться (и сам аккуратно его перехватывает, поэтому снаружи ты никогда не видишь эту ошибку при обычном `for`).

Отсюда важное терминологическое различие, которое стоит закрепить сразу:

- **Итерируемый объект (iterable)** — любой объект, у которого есть метод `__iter__()`. Список, строка, словарь, диапазон `range(...)` — всё это итерируемые объекты.
- **Итератор (iterator)** — объект, у которого есть **и** `__iter__()`, **и** `__next__()`. Итератор — это как закладка в книге: он помнит, на каком месте остановился.

Список — итерируемый объект, но **не** итератор. Убедиться в этом легко: у списка нет метода `__next__`, и, если вызвать `iter()` на одном и том же списке дважды, каждый раз получится новый, независимый итератор — с нуля:

```python
data = [1, 2, 3]
for x in data:
    print(x)   # 1 2 3
for x in data:
    print(x)   # снова 1 2 3, а не пусто!
```

Если бы список сам был итератором (то есть помнил бы, «докуда дошёл»), второй цикл ничего бы не напечатал — «закладка» осталась бы на конце после первого прохода. Но список каждый раз создаёт новый итератор, поэтому проходить по нему можно сколько угодно раз.

## 1.5. Пишем свой собственный итератор

Чтобы окончательно снять всю таинственность, напишем класс, который сам реализует протокол итератора — то есть определяет `__iter__` и `__next__` вручную:

```python
class CountDown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        value = self.current
        self.current -= 1
        return value
```

Разберём построчно:

- `__init__` — обычный конструктор, сохраняет стартовое число.
- `__iter__` возвращает `self` — то есть сам объект. Это стандартный приём: если объект уже умеет быть итератором (у него есть `__next__`), он может выступать «итератором самого себя».
- `__next__` — сердце всей конструкции. Если счётчик дошёл до нуля — поднимаем `StopIteration`, сигнализируя «данные закончились». Иначе — возвращаем текущее значение и уменьшаем счётчик для следующего вызова.

Проверим, что такой объект действительно работает с обычным `for`, как будто это список:

```python
for x in CountDown(3):
    print("countdown:", x)
# countdown: 3
# countdown: 2
# countdown: 1
```

А теперь — вручную, шаг за шагом, чтобы увидеть механику без синтаксического сахара `for`:

```python
cd = CountDown(2)
it = iter(cd)
print(it is cd)    # True — потому что __iter__ вернул self

print(next(it))     # 2
print(next(it))     # 1
try:
    next(it)
except StopIteration:
    print("StopIteration поймано")   # эта строка выполнится
```

`it is cd` печатает `True` — это подтверждает, что `__iter__` у нашего класса вернул именно `self`, то есть объект `CountDown` сам является своим собственным итератором. Третий вызов `next(it)` поднимает `StopIteration`, потому что `self.current` уже стал `0`.

Написание отдельного класса с `__iter__`/`__next__` ради простой последовательности чисел — довольно громоздко для такой простой задачи. В следующем пункте — способ сделать то же самое в четыре строки.

## 1.6. Генераторы: ленивые функции с `yield`

Python даёт короткий путь для создания итераторов: функцию, в теле которой встречается ключевое слово `yield`. Такая функция называется **генераторной функцией**, а объект, который она возвращает при вызове, — **генератором**.

```python
def countdown_gen(start):
    print("генератор стартовал")
    current = start
    while current > 0:
        yield current
        current -= 1
```

Выглядит как обычная функция с циклом, но ведёт себя совсем не так, как обычная функция. Смотри внимательно:

```python
gen = countdown_gen(3)
print(type(gen))   # <class 'generator'>
```

Обрати внимание: строка `"генератор стартовал"` **не напечаталась**. Это ключевой момент, который стоит запомнить надолго: **вызов генераторной функции не выполняет её тело**. Он лишь создаёт объект-генератор, который *готов* когда-нибудь начать выполнение, но пока ещё палец о палец не ударил.

Работа начинается только тогда, когда мы явно запрашиваем у генератора значение через `next()`:

```python
print(next(gen))   # печатает "генератор стартовал", затем возвращает 3
print(next(gen))   # 2
print(next(gen))   # 1
try:
    next(gen)
except StopIteration:
    print("генератор исчерпан")
```

Вот что происходит на каждом `next(gen)`:

1. Выполнение тела функции **начинается или возобновляется** с того места, где оно в прошлый раз остановилось.
2. Оно идёт вперёд до первого встреченного `yield current` — на этой строке выполнение **замирает**, а значение `current` отдаётся наружу как результат `next(gen)`.
3. При следующем `next(gen)` выполнение **продолжается ровно с того же места** — то есть сразу после `yield`, — как будто функция никуда и не уходила. При этом все локальные переменные (в нашем случае `current`) сохраняют свои значения — они не сбрасываются между вызовами.
4. Когда цикл `while` заканчивается и функция естественным образом доходит до конца (без очередного `yield`), генератор поднимает `StopIteration` — точно так же, как это делал наш собственный класс `CountDown` в прошлом пункте.

Это и есть главное отличие `yield` от `return`: `return` завершает функцию полностью и безвозвратно, а `yield` — временно приостанавливает, сохраняя всё состояние, чтобы можно было продолжить с того же места позже.

Генератор точно так же работает с `for` — просто напрямую, без всяких ручных `next()`:

```python
for x in countdown_gen(3):
    print("for gen:", x)
# генератор стартовал
# for gen: 3
# for gen: 2
# for gen: 1
```

Обрати внимание: строка `"генератор стартовал"` напечаталась заново — потому что `countdown_gen(3)` здесь вызывается ещё раз и создаёт совершенно новый, независимый генератор со своим собственным состоянием, точно как в примере со списком в пункте 1.4.

**Почему это важно для будущих модулей.** Держи в голове две вещи, которые мы только что увидели своими глазами:

- Вызов функции, определённой специальным образом, **не запускает её тело сразу** — вместо этого возвращается объект, который лишь *обещает* когда-то начать работу.
- Реальная работа происходит по кусочкам, с паузами, и между паузами всё состояние функции сохраняется в целости.

В модуле 4 мы увидим, что `async def` устроена ровно по этому же принципу: вызов `async`-функции тоже не выполняет её тело немедленно, а возвращает объект (корутину), а слово `await` внутри неё работает очень похоже на `yield` — временно отдаёт управление, сохраняя всё состояние, чтобы продолжить позже. Мы специально не забегаем вперёд с деталями сейчас — просто зафиксируй этот принцип, он окажется до боли знакомым через три модуля.

## 1.7. Генераторные выражения

Есть ещё более компактный способ создать генератор — без `def` и `yield` вообще, синтаксисом, похожим на списковое включение (list comprehension), но в круглых, а не квадратных скобках:

```python
squares = (x**2 for x in range(5))
print(type(squares))    # <class 'generator'>
print(list(squares))     # [0, 1, 4, 9, 16]
```

`(x**2 for x in range(5))` — это **генераторное выражение**. Оно ничем принципиально не отличается от генераторной функции из прошлого пункта — точно так же ничего не вычисляет сразу, а лениво отдаёт значения по одному, когда их запрашивают.

Разница с привычным списковым включением `[x**2 for x in range(5)]` принципиальна и легко измеряется:

```python
import sys

gen_expr = (x for x in range(1_000_000))
lst = [x for x in range(1_000_000)]

print(sys.getsizeof(gen_expr))   # 192 (байта)
print(sys.getsizeof(lst))        # 8 448 728 (байта, то есть ~8.4 МБ)
```

Списковое включение `[...]` сразу же вычисляет **все** значения и держит их в памяти одним куском — список на миллион чисел занимает порядка восьми с половиной мегабайт. Генераторное выражение `(...)` не хранит ничего, кроме «правила», как получить следующее значение, — оно весит те же 192 байта что для миллиона чисел, что для одного, что для бесконечной последовательности.

Практический смысл для бэкенда, к которому мы придём: если тебе нужно обработать огромный файл, результат SQL-запроса на миллионы строк или бесконечный поток данных, генератор позволяет работать с этим по одному элементу за раз, не пытаясь запихнуть всё сразу в оперативную память сервера.

## 1.8. `yield from`: один генератор внутри другого

Иногда генератор хочет не просто выдать значение сам, а «одолжить» на время выдачу значений у другого генератора (или любого итерируемого объекта). Для этого есть специальная конструкция `yield from`:

```python
def inner():
    yield 1
    yield 2

def outer():
    yield "start"
    yield from inner()
    yield "end"

print(list(outer()))   # ['start', 1, 2, 'end']
```

`yield from inner()` — это по смыслу то же самое, что написать вручную:

```python
for value in inner():
    yield value
```

— но короче и, как мы увидим в модуле 4, чуть более функционально: `yield from` умеет прозрачно пробрасывать не только значения, но и исключения между «внешним» и «внутренним» генератором. Сейчас достаточно запомнить сам факт: один генератор может делегировать часть своей работы другому, и снаружи это выглядит как один непрерывный поток значений — `'start'`, затем всё, что выдал `inner()`, затем `'end'`.

Забегая вперёд совсем коротко (детали — в модуле 4): исторически, до того как в Python появился отдельный синтаксис `async`/`await`, асинхронный код писали именно через `yield from`. Современный `await` — это, по сути, более удобная и понятная запись той же самой идеи «приостановиться здесь и передать управление куда-то ещё, пока не будет результата». Если тебе сейчас это не до конца понятно — это нормально, это буквально тема следующих модулей. Главное — конструкция `yield from` не будет для тебя чем-то совсем новым, когда мы до неё доберёмся.

## Итог модуля: словарь понятий

| Термин | Что значит |
|---|---|
| **Объект** | всё, что можно положить в переменную; в Python это касается и чисел, и строк, и функций |
| **Функция высшего порядка** | функция, которая принимает другую функцию как аргумент или возвращает функцию как результат |
| **Замыкание (closure)** | внутренняя функция, которая продолжает иметь доступ к переменным окружающей её функции даже после того, как та завершилась |
| **`nonlocal`** | ключевое слово, разрешающее внутренней функции *изменять* (а не только читать) переменную из окружающей функции |
| **Итерируемый объект (iterable)** | объект с методом `__iter__()`; из него можно получить итератор |
| **Итератор (iterator)** | объект с методами `__iter__()` и `__next__()`; помнит, на каком месте остановился |
| **`StopIteration`** | исключение, которым итератор сигнализирует «значения закончились»; `for` перехватывает его автоматически |
| **Генераторная функция** | функция с `yield` в теле; при вызове не выполняется сразу, а возвращает объект-генератор |
| **Генератор** | объект, который умеет по частям, с паузами выполнять тело генераторной функции, сохраняя состояние между паузами |
| **Генераторное выражение** | компактная запись `(... for ... in ...)`, создающая генератор без явного `def`/`yield` |
| **`yield from`** | делегирование выдачи значений другому генератору или итерируемому объекту |

## Чек-поинт

**1. В чём разница между `greet` и `greet()`?**
Ответ: `greet` — это ссылка на сам объект функции, без вызова. `greet()` — вызов функции, выполнение её тела и получение результата.

**2. Что выведет этот код и почему:**
```python
def make_counter():
    count = 0
    def counter():
        nonlocal count
        count += 1
        return count
    return counter

a = make_counter()
b = make_counter()
print(a(), a(), b())
```
Ответ: `1 2 1`. `a` и `b` — результаты двух отдельных вызовов `make_counter()`, у каждого своя независимая замкнутая переменная `count`. Два вызова `a()` подряд дают `1`, затем `2`; первый вызов `b()` начинает отсчёт заново, с `1`.

**3. Что произойдёт, если убрать `nonlocal count` из примера выше?**
Ответ: программа упадёт с `UnboundLocalError` при первом же вызове `counter()` — без `nonlocal` строка `count += 1` пытается создать новую *локальную* переменную `count`, а справа от `+=` она ещё не определена в локальной области видимости.

**4. Почему список (`list`) — итерируемый объект, но не итератор?**
Ответ: у списка есть `__iter__()`, но нет `__next__()`. Он не умеет сам себя «прокручивать» — вместо этого при каждом вызове `iter(список)` создаётся новый, независимый итератор, который и умеет отдавать элементы по одному и запоминать позицию.

**5. Что выведет этот код и почему:**
```python
def gen():
    print("A")
    yield 1
    print("B")
    yield 2

g = gen()
print("создан")
print(next(g))
print(next(g))
```
Ответ:
```
создан
A
1
B
2
```
Вызов `gen()` не печатает `"A"` сразу — тело не выполняется до первого `next()`. Первый `next(g)` выполняет код до первого `yield` (печатает `"A"`, возвращает `1`). Второй `next(g)` продолжает с места остановки (печатает `"B"`, возвращает `2`).

**6. Чем генераторное выражение `(x for x in range(10**6))` выгоднее списка `[x for x in range(10**6)]`, если тебе нужно просто пройтись по значениям один раз?**
Ответ: генератор не хранит все значения в памяти сразу — он весит несколько сотен байт независимо от того, сколько элементов «внутри», в отличие от списка, который сразу выделяет память под все элементы (для миллиона чисел — порядка восьми мегабайт).
