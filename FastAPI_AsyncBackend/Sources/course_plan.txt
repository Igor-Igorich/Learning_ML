# Курс: «FastAPI и Асинхронный Бэкенд» (ML & Backend) — Финальный план

## Модуль 0. Пролог: зачем это нужно

**0.1. Синхронный мир и его предел**
- Что происходит, когда сервер ждёт: блокировка потока, ожидание I/O, простой CPU.
- Парадокс: 10 000 одновременных пользователей ≠ 10 000 ядер CPU.
- Почему ML-сервисы особенно чувствительны к задержкам: inference как «тяжёлая» задача, которую нельзя просто воткнуть в цикл событий.

**0.2. Ландшафт решений**
- Многопоточность (GIL, threading), мультипроцессинг, асинхронность — когда что применять.
- Почему FastAPI, а не Flask/Django/Express/Go.
- Roadmap курса: от «Hello, World» до продакшн-архитектуры.

## Модуль 2. Асинхронное программирование: теория и практика

**2.1. Конкурентность, параллелизм, кооперативная многозадачность**
- Различия: concurrency vs parallelism.
- Вытесняющая vs кооперативная многозадачность.
- Модель акторов, CSP, callback-hell — исторический контекст.
- *Математическая подоплека:* конечные автоматы, машины состояний, переходы по событиям (event-driven model).

**2.2. Событийный цикл (Event Loop)**
- Что такое event loop: очередь событий, цикл обработки, select/poll/epoll/kqueue.
- Однопоточность цикла: почему `time.sleep(10)` убивает производительность.
- `asyncio.get_event_loop()`, `loop.run_until_complete()`, `loop.run_forever()`.
- *Математическая подоплека:* очереди (FIFO), дисциплины обслуживания, неблокирующий I/O как системный вызов.

**2.3. Корутины: `async` / `await`**
- Корутина как объект: `async def`, `Coroutine`, `Future`, `Task`.
- Ключевое слово `await`: точка уступки управления (yield control).
- Разница между корутиной, задачей и фьючерсом.
- Состояния корутины: pending, running, done, cancelled.
- *Математическая подоплека:* корутины как сопрограммы в теории вычислений; continuation-passing style.

**2.4. Параллельное выполнение корутин**
- `asyncio.gather()`: параллельный запуск, обработка результатов и исключений.
- `asyncio.wait()`: тонкое управление (return_when, timeout).
- `asyncio.as_completed()`: потоковая обработка по готовности.
- `asyncio.create_task()`: фоновые задачи, отмена (`task.cancel()`), таймауты (`asyncio.timeout` / `wait_for`).

**2.5. Синхронизация в асинхронном коде**
- `asyncio.Lock`, `Semaphore`, `BoundedSemaphore`: защита разделяемых ресурсов.
- `Event`, `Condition`, `Barrier`: сигнализация между корутинами.
- Проблема «голодания» и справедливости (fairness) в очередях.
- *Математическая подоплека:* взаимное исключение, семафоры Дейкстры, deadlock и livelock.

**2.6. Потоки и процессы в гибридной модели**
- `loop.run_in_executor()`: ThreadPoolExecutor и ProcessPoolExecutor.
- CPU-bound задачи в асинхронном коде: GIL, `ProcessPoolExecutor` для ML-инференса.
- Паттерн «основной цикл + пул воркеров» для тяжёлых вычислений.

**2.7. Асинхронные генераторы и контекстные менеджеры**
- `async for`, `async with`: протоколы `__aiter__`, `__anext__`, `__aenter__`, `__aexit__`.
- Потоковая обработка данных: чтение по частям, backpressure.

## Модуль 3. Сетевое программирование и протоколы

**3.1. Модель OSI и TCP/IP**
- Уровни абстракции: от физического до прикладного.
- TCP: установление соединения (three-way handshake), надёжность, потоковость, окно congestion.
- HTTP как текстовый протокол поверх TCP.
- *Математическая подоплека:* конечные автоматы для TCP (ESTABLISHED, CLOSE_WAIT и т.д.), алгоритмы контроля перегрузки (AIMD).

**3.2. HTTP/1.1, HTTP/2, HTTP/3**
- Проблема head-of-line blocking в HTTP/1.1.
- Мультиплексирование в HTTP/2: фреймы, потоки, приоритизация.
- HTTP/3 и QUIC: переход на UDP, устранение блокировки на уровне транспорта.
- Почему это важно для FastAPI (Uvicorn + H11/HTTPCore).

**3.3. WebSocket**
- Протокол: handshake, фреймы, маскирование, ping/pong.
- Дуплексное соединение: отличие от HTTP.
- Когда WebSocket, а когда SSE (Server-Sent Events).

**3.4. Асинхронные сетевые библиотеки**
- `asyncio` низкого уровня: `StreamReader`, `StreamWriter`.
- `aiohttp` как клиент: сессии, коннекшн-пулы, таймауты.
- Сравнение с `httpx`: HTTP/2 support, синхронный и асинхронный API.

## Модуль 4. FastAPI: архитектура, жизненный цикл и обработка запросов

**4.1. Философия фреймворка**
- Starlette (ASGI) + Pydantic = FastAPI.
- Type-driven development: как типы становятся документацией и валидацией.
- Сравнение с Django REST Framework, Flask-RESTX: декларативность vs императивность.

**4.2. ASGI: от WSGI к асинхронности**
- Почему WSGI не поддерживает асинхронность: синхронный callable.
- ASGI-интерфейс: `scope`, `receive`, `send`.
- Uvicorn, Hypercorn, Daphne: серверы приложений.
- Жизненный цикл запроса в ASGI-приложении.

**4.3. Маршрутизация и обработчики**
- `APIRouter`, включение роутеров, префиксы, теги.
- Path parameters: типизация, валидация через Pydantic.
- Query parameters: обязательные, опциональные, `Query(..., ge=0, le=100)`.
- Request Body: `BaseModel`, вложенные модели, списки.
- Заголовки, куки, файлы (`UploadFile`), формы (`Form`).

**4.4. Pydantic V2: модели данных и внутреннее устройство**
- `BaseModel`: поля, типы, дефолты.
- Валидация: `Field`, `field_validator`, `model_validator`.
- Сериализация: `model_dump()`, `model_dump_json()`, `ConfigDict`.
- **Внутреннее устройство Pydantic V2:** ядро на Rust (`pydantic-core`), zero-copy парсинг JSON, сравнение производительности с V1 и стандартным `json`.
- *Математическая подоплека:* схемы JSON Schema как формальная грамматика; валидация как распознавание языка.

**4.5. Ответы клиенту**
- `Response`, `JSONResponse`, `HTMLResponse`, `StreamingResponse`, `FileResponse`.
- Статус-коды, заголовки ответа.
- Сериализация сложных объектов: `jsonable_encoder`.

**4.6. Обработка ошибок и исключений**
- `HTTPException`: статус-коды, заголовки, детали.
- **Кастомные Exception Handlers:** регистрация `@app.exception_handler()`, иерархия исключений, глобальная централизованная обработка.
- Логирование ошибок: уровни, трассировки, корреляционные ID.
- Преобразование бизнес-исключений в HTTP-ответы.

**4.7. Middleware: BaseHTTPMiddleware vs чистые ASGI-мидлвари**
- `BaseHTTPMiddleware`: простота написания, внутренняя механика, риск блокировки event loop синхронными вызовами.
- **Чистые ASGI-мидлвари:** ручная обработка `scope`/`receive`/`send`, полный контроль, отсутствие накладных расходов.
- Порядок выполнения middleware, влияние на latency.
- Практика: middleware для логирования, таймингов, добавления заголовков.

**4.8. Жизненный цикл приложения (Lifespan)**
- **События lifespan:** `startup`/`shutdown`, `@asynccontextmanager`, `AsyncExitStack`.
- Управление глобальным состоянием через `app.state`.
- **Практика для ML:** разовая загрузка модели в оперативную память при старте, инициализация пула соединений, подогрев кэша.
- Graceful shutdown: корректное освобождение ресурсов, drain pending requests.

## Модуль 6. Асинхронная работа с базами данных

**6.1. Реляционные БД: теория для практика**
- ACID, уровни изоляции транзакций (Read Uncommitted → Serializable).
- Феномены: dirty read, non-repeatable read, phantom read, lost update.
- Индексы: B-Tree, Hash, частичные и покрывающие индексы.
- *Математическая подоплека:* теория реляционных баз (Кодд), реляционная алгебра (селекция, проекция, соединение).

**6.2. SQLAlchemy 2.0: асинхронный стиль**
- `create_async_engine`, `AsyncSession`, `select()`, `async_sessionmaker`.
- 1.x vs 2.x: query-style vs select-style.
- **Асинхронные контекст-менеджеры:** `async with sessionmaker() as session`, `async with session.begin()`.
- Connection pooling: `QueuePool`, настройка размера пула, overflow.

**6.3. Интеграция SQLAlchemy с FastAPI**
- Паттерн «сессия на запрос»: зависимость `get_db()` с `yield` и `AsyncSession`.
- Управление транзакциями через зависимости и контекстные менеджеры.
- Обработка deadlock-ов и retry-логика на уровне приложения.

**6.4. Миграции: Alembic**
- Версионирование схемы, `alembic revision`, `upgrade`, `downgrade`.
- Автогенерация миграций, проверка корректности.
- Миграции в CI/CD.

**6.5. NoSQL и специализированные хранилища**
- `motor` для MongoDB: асинхронный драйвер.
- Redis: `redis-py` (async), кэширование, pub/sub, rate limiting.
- Векторные БД для ML: Pinecone, Weaviate, Qdrant, Chroma — когда и зачем.

**7.3. Авторизация и RBAC**
- Разграничение прав: роли, разрешения, политики.

**7.4. Безопасность приложения**

## Модуль 9. Интеграция ML в асинхронный бэкенд

**9.1. Архитектурные паттерны ML-инференса**
- Синхронный inference в endpoint: когда допустимо (модели < 100 мс).
- Асинхронный inference: очереди задач, фоновая обработка.
- Batch inference: накопление запросов, динамический батчинг.
- *Математическая подоплека:* теория очередей (M/M/1, M/M/c), закон Литтла, оптимальный размер батча.

**9.2. ML-серверы и форматы моделей**
- ONNX Runtime, TensorRT, OpenVINO: ускорение inference.
- TorchServe, Triton Inference Server, BentoML: специализированные серверы.
- Отделение ML-сервиса от API-сервиса: микросервисная архитектура.

**9.3. Фоновые задачи в FastAPI**
- `BackgroundTasks`: простые фоновые операции, ограничения (потеря задач при рестарте).
- Интеграция с Celery: брокеры (Redis, RabbitMQ), workers, мониторинг (Flower).
- Современные альтернативы: `arq` (async-native), `dramatiq`, `saq`.

**9.4. Потоковая обработка и WebSocket для ML**
- StreamingResponse для генеративных моделей (token-by-token).
- WebSocket для real-time inference (распознавание речи, видео).
- Server-Sent Events (SSE) для прогресс-баров длинных вычислений.

**9.5. Feature Store и управление данными**
- Оффлайн vs онлайн фичи.
- Feast, Tecton: концепция feature store.
- Кэширование фичей в Redis для low-latency inference.

## Модуль 11. Архитектура и паттерны проектирования

**11.1. Чистая архитектура и слоистая структура**
- Слои: Presentation (API), Application (Use Cases), Domain (Entities), Infrastructure (DB, External).
- Dependency Rule: зависимости направлены внутрь.
- Интерфейсы в Python: `Protocol`, абстрактные классы.

**11.2. Паттерны для асинхронных систем**
- Circuit Breaker: предотвращение каскадных отказов.
- Retry с экспоненциальным backoff и jitter.
- Idempotency Key: безопасные повторные запросы.
- Outbox Pattern: надёжная публикация событий.
- Saga: управление распределёнными транзакциями.

**11.3. API-дизайн**
- REST: ресурсы, HTTP-методы, статус-коды, HATEOAS (прагматично).
- RPC-style: когда уместен (ML inference endpoints).
- Версионирование API: URL vs заголовки.
- Пагинация, фильтрация, сортировка.
- OpenAPI: генерация спецификации, клиентских SDK.

**11.4. Микросервисы и распределённые системы**
- Когда монолит, когда микросервисы.
- Межсервисное взаимодействие: REST, gRPC, message brokers.
- Service Discovery, API Gateway (Kong, Traefik).
- *Математическая подоплека:* CAP-теорема, теорема PACELC, консенсус (Raft, Paxos) — интуиция без доказательств.

**11.5. REST API vs Event-Driven архитектура**
- **Пространственная связанность (spatial coupling):** REST требует знания адреса сервиса; Event-Driven — публикация в брокер.
- **Временная связанность (temporal coupling):** REST требует одновременной доступности; Event-Driven — асинхронность и буферизация.
- **Лавинные нагрузки (thundering herd):** как REST-пolling провоцирует пики, а Event-Driven с бэкпрессуром их сглаживает.
- Message Brokers: RabbitMQ (AMQP), Apache Kafka (log-based), NATS (lightweight pub/sub).
- Паттерн CQRS: разделение команд и запросов.
- Выбор архитектуры под задачу: real-time ML inference vs batch processing vs event streaming.

## Модуль 12. Кейсы и финальный проект

**12.1. Кейс 1: ML API для real-time классификации**
- Загрузка изображения → предобработка → inference ONNX → ответ.
- Оптимизация: batching, кэширование результатов, rate limiting.

**12.2. Кейс 2: Чат-бот с генеративной моделью**
- Streaming ответов через SSE.
- Управление контекстом диалога, ограничение токенов.
- Фоновая обработка аналитики.

**12.3. Кейс 3: Рекомендательная система**
- Feature retrieval из Redis/Feature Store.
- A/B testing инфраструктура: разделение трафика, метрики.
- Логирование feedback loop.

**12.4. Финальный проект**
- Полноценный асинхронный бэкенд для ML-сервиса.
- Требования: аутентификация, БД, фоновые задачи, тесты, метрики, деплой.
- Код-ревью, оптимизация по профилировщику.
